3. Gap 1: OCR Escalation Never Fires on Image-Only PDFs

Critical P1 — ~35 lines

Impact: 6 documents produce completely blank output (0 text chars in 4 docs, 58–73 chars in 2 partial docs).

Root Cause

validate_tree() checks node_count < 3 before garbling. Image-only PDFs produce only <!-- image --> blocks, fail on structure, and route to FLAT-03 — which has zero image-density awareness. OCR escalation at client.py is gated on reason == "garbling", making it structurally unreachable for these documents.

client.py — OCR escalation (garbling-only gate)
client.py — FLAT-03 routing (no image check)
helpers.py — validate_tree priority order
converters.py — DOCLING_DO_OCR default "0"

Proposed Fix

Insert image-ratio pre-check at client.py before FLAT-03 routing: if <!-- image --> lines exceed 50% of total lines in a PDF, force one force_full_page_ocr retry with language detection from filename. Reuses existing detect_ocr_langs, ensure_tessdata, pdf_to_markdown_docling, and OCR_ESCALATION_TOTAL metrics. If OCR fails, falls through to FLAT-03 as before — no worse than today.

4. Gap 2: Garble-Gate Checks Structure Only

High P2 — ~43 lines

Impact: 3 documents with semantically garbage text persist as "successful" — PUA mojibake (21% weird chars), Latin substitution ("آل Oleg"), and 86% digit-junk.

Root Cause

_tree_is_garbled() at helpers.py only checks: empty blob, NUL (\x00), replacement char (U+FFFD), and control-char ratio >5%. Three corruption types sail through as valid Unicode. Worse: the flat-doc path bypasses the garble check entirely — 4f37b2e3 (86% digit-junk) fails on structure, routes to FLAT-03, and is persisted without any text-quality check.

helpers.py — _tree_is_garbled (narrow heuristics)
helpers.py — route_and_extract_flat (no quality gate)
client.py — FLAT-03 routing

Proposed Fix (Two Parts)

Part A — Extend _tree_is_garbled (+15 lines at helpers.py):
• PUA-char ratio > 3% → garbled (catches font/CMap mojibake)
• Digit ratio > 60% on blobs > 500 chars → garbled (catches numeric junk)
• Single-token repetition > 30% of all words → garbled (catches "1651001429"×3481)

Part B — _flat_text_is_garbled(md) — ✅ Already implemented (2026-07-18) in helpers.py. Wired in client.py (FLAT-03 block). Treat this half of Gap 2 as covered; no further action needed.
False-Positive Safety
  • PUA 3%: German insurance PDFs have 0% PUA. Only broken CMaps produce PUA. Very safe.
  • Digit 60%: Even world-stats-pocketbook (heavy numbers) is <30% digits due to headers/labels. Safe.
  • Repetition 30%: Normal docs never have one word >5% of total. Safe.

5. Gap 3: Heading-Depth Drift Traps Article Markers

Critical P0 (reprocess) + P2 (code fix ~30 lines)

Impact: 553 Article markers trapped in tail-blobs across 6 documents (worst: 236k chars, 457 markers in one leaf).

Root Cause (Corrected)

Not inline markers — every trapped Article uses correct heading syntax (### Article (10)). The real defect is heading-depth drift: Docling assigns increasing heading depths (##→###→####→######) to structurally-identical Article headers as font-size cues drift across pages. Additionally, Docling emits headings with leading whitespace (    ### Article (10)) which CommonMark doesn't recognize as headings, so the tree builder treats them as body text.

helpers.py — split_oversized_leaf_nodes
helpers.py — _OVERSIZED_ORDINAL_RE
converters.py+ — pdf_to_markdown_docling output

Fix: Two Layers

Layer 1 (P0, 0 lines): Re-process 2 stale docs (2030e34d, 2a7e0ebe) processed before Fix-1 landed (2026-06-29 vs Fix-1 on 2026-07-01). The current splitter already handles them — confirmed by running the regex against the 236k leaf (425 matches found).
Layer 2 (P2, ~30 lines): Normalize indented headings in pdf_to_markdown_docling() output — strip leading whitespace before # heading markers so the tree builder recognizes them. This fixes the 4 post-Fix-1 docs (144fbaaf, 1d682268, 4806d4bd, 14f41037) whose leaves are 21–42k chars (under the 50k splitter threshold, but oversized vs the 514-char healthy average).

7. Gap 5: Arabic Text Quality

High

5a: في→# Substitution P3

Impact: 2,923 occurrences in b87e897e (Federal Decree-Law 33 Arabic). The high-frequency grammatical particle "في" ("in") is replaced by #, damaging sentence meaning at scale.

Docling bug, not the PDF. pdftotext extracts 162 clean في and zero # from the same PDF. The substitution is introduced by Docling's markdown serialization. Fix options:
• Upstream: File against Docling (proper fix)
• Interim post-process: After pdf_to_markdown_docling, replace inline # (not line-initial headings) with في in Arabic-dominant text. Fragile but effective.

5b: RTL Table Word-Order Reversal Trade-off

Impact: 97% of table rows in 70607efb have intra-cell word reversal (e.g., "إدارة البيانات" → "البيانات ة إدار"). Prose/headings outside tables are clean.

Upstream Docling/TableFormer limitation. The table extractor reads cell text by physical x-coordinate (L→R) instead of respecting the bidi algorithm. table_is_rtl() exists in helpers.py but only affects continuation-table column ordering, not within-cell word order. No fix surface in our code. Mitigation: flag RTL tables with bidi_scrambled: true in quality metadata.

8. Gap 6: Table Column Degradation

Medium–High

6a: Multi-Row Header Flattening Trade-off

18286d95 (GHV-TKV-Tarif): 2-row header hierarchy ("Hund" > "ab 45cm" > "OP-Versicherung" > "Basis") collapsed to "Hund" repeated 12×. TableFormer's markdown export loses rowspan/colspan. No fix surface — rowspan info is lost before it reaches our pipeline.

6b: Icon/Checkmark Cell Loss Trade-off

45c9e0b4 (Unfallversicherung): 81% image blocks, empty_cell_ratio up to 0.75. Checkmark icons are rasterized per-cell, not text. Even with OCR, Tesseract can't reliably classify tiny icon glyphs. Already flagged via suspected_miss: true in quality metadata.

6c: TOC-as-Table Misclassification P1 — ~20 lines

621512a9 (World Stats Pocketbook): 265 table blocks, many are actually TOC/index pages with dot-leader formatting (Country....83) misdetected as data tables.

Quick fix: Add a _looks_like_toc_page heuristic in route_and_extract_flat — check for dot-leader density (\.{4,}) and trailing page-number pattern before committing a block as role: table. Similar to existing _looks_like_frontmatter_toc guard in the splitter.
