RFC-050 & RFC-051 — Iteration 5 Review Report

Date: 2026-09-24  |  Iteration: 5 of rfc-iterate  |  Reviewer agents: erasure-sha256-gap, load-raw-dual-key  |  Coordinator verification: source checked via codebase-memory + grep

Summary: The uploads/<sha256[:8]>/ key that Iteration 4 introduced for rejected documents could not be erased, discovered or retrieved, and was prone to collisions. Rejected-document markdown now goes to quarantine/<sha256>.extracted.md, using RFC-049's full-sha256 key and its existing erasure functions, and stays unserved (HR5). The coordinator's check also showed that Iteration 4 put the flat reject point in the wrong function: it is in _persist_flat_result, not index(). Per the user, RFC-049's 30-day quarantine lifecycle TTL is superseded (new RFC-050 D6). RFC-050 effort 24-32h → 25.5-33.5h. RFC-051 is unchanged: no overlap with quarantine or erasure.

Review Agents & Findings

Agent 1: erasure-sha256-gap

#FindingTypeResolution
F1 The reject-path raw output is orphaned. _erase_uploads prefix-deletes uploads/{ctx.doc_id}/, so it would work for any string key. But rejected documents never get a registry row, so nothing ever calls delete_doc(sha256[:8]). There is no discovery path and no expiry. HR2 gap FIXED — the key moved to quarantine/<sha256>.extracted.md, which RFC-049's erasure paths reach.
F2 The key space didn't match quarantine. save_quarantine writes quarantine/{sha256}.json + .meta.json using the full sha256 (storage/documents.py:888-942). Verified by coordinator. Design inconsistency FIXED — same full-sha256 key.
F3 8 hex characters = 32 bits: about a 1% chance of a collision at roughly 77k documents. Correctness risk FIXED — the full sha256 is used.

Agent 2: load-raw-dual-key

#FindingTypeResolution
F4 No retrieval path. load_raw(doc_id) and get_raw_output(doc_id) take a doc_id only. The registry can look up sha256 from a doc_id but not the other way round, and rejected documents have no row. The agent recommended renaming the parameter to key and adding list_raw_outputs(). API design RESOLVED (user) — persisted documents only. Serving rejected content over MCP would go against HR5. New Design Property 3a: a non-doc_id key returns not-found and nothing reads quarantine/. The rename and the discovery tool were rejected.
