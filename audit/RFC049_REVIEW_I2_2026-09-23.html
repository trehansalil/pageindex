Verdict

Iteration 1's Option C could not have been implemented as written. Four blocking defects are now resolved inline, and the triad is internally coherent.

Option C (reject and quarantine) still stands as the decision, but four of its mechanisms depended on things that do not exist in the code:

  • a doc_id at the reject sites;
  • a flat guard that actually fires;
  • a route-safe override condition;
  • a per-document decision trail.

All four are corrected with verified file:line anchors. The two CLAUDE.md edits (HR2 and HR5) are proposed as a diff only and still need human approval. Link check: 0 broken anchors across 518 markdown links in the three files.

Erasure cascade position

_erase_quarantine runs after meta_json (step 3) and before redis_cache (step 4).

The step needs ctx.sha256. _erase_verdicts sets that field (step 2d) before _erase_meta_json deletes the sidecar, and ErasureContext keeps it after the deletion.

The dependency is declared, not left implicit. The verdicts step gets produces={"ctx.sha256"} and quarantine gets consumes={"ctx.sha256"}, so the D4 ordering loop in validate_erasure_manifest() rejects any reorder that breaks it.

This position keeps HR2's order: MinIO derivatives, then the diagnostic copy, then Redis. If no sha256 can be found, the step returns False (required=False) and the operator helper erase_quarantine(sha256) applies.

Lifecycle-config finding

There is no MinIO lifecycle configuration anywhere in the repo. None of set_bucket_lifecycle, LifecycleConfig or mc ilm appears in src/, scripts/, Makefile, docker-compose.yml, services/ or docs/, and uploads/staging/ has no rule either. The only expiries are presigned-URL lifetimes and Redis TTLs.

So there was no existing rule to reference. Task 7.5c adds an operator step: mc ilm rule add --prefix "quarantine/" --expire-days 30. It is documented through Task 7.8, and nobody owns it yet.
