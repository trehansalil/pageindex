1. Executive Conclusion

Overall Assessment: CONDITIONALLY APPROVED with 3 mandatory amendments

RFC-041 correctly identifies the generative defect cycle and targets real, verified defects across all 8 architecture zones. 8 of 9 structural claims verified exactly as stated against the codebase; one claim (the source_selection bypass at verdict.py:479) is stale — the bypass is already scoped to image-enrichment only, not the 5-path hole the audit describes.

However, three critical gaps prevent approval as-is:

  1. D3 is under-specified. finalize_gate_and_route (types.py:358) cannot express route overrides — 5 of the 8 recovery.py mutations are deliberate post-hoc overrides, not "missed finalizer calls." Implementing D3 as written would silently break RTL-comparison, VLM-tesseract-recovery, flat-prefer, and landscape-reroute behavior.
  2. D11's async wrapper is wrong. The task spec calls for asyncio.run() inside already-async callers (promotion_sweep.run_sweep, preprocess_client.recompute_verdicts). This would crash with RuntimeError: asyncio.run() cannot be called from a running event loop.
  3. Zone 2 is genuinely orphaned. RFC-040 self-marked done; RFC-041 defers via NG2. The dead "Arabic" branch at garble.py:583 is inside the canonical entry point D1 consolidates through — the safety net never fires. No deliverable, no owner, no gate covers the remaining 7 post-NFKC _infer_presentation_forms call sites.

What the RFC gets right

  • The "generative defect cycle" diagnosis is accurate: point fix → compensating heuristic → draft RFC → next wave inherits both
  • All 11 ExtractionState direct mutations in recovery.py verified at exact line numbers (6 route, 2 ok, 3 rtl_decision)
  • The garble.py:750 bypass, flat.py:175/:200 accessor divergence, gates.py:375/:383 tuple-keyed double-fire, and verdict 5-writer problem are all real and correctly located
  • Wave sequencing is largely correct — D4 is genuinely independent, D10 is cheap and high-value, D6/D7 testing belongs after production fixes

What the RFC gets wrong or leaves unaddressed

  • D3 treats override mutations as "unauthorized writes" when 5 of 8 are intentional post-gate overrides driven by orthogonal signals (RTL comparison, VLM fallback, density heuristic, landscape detection)
  • D2's file scope omits garble.py itself, which calls _node_text_parts at :648/:685 and _flat_block_primary_text at :780
  • D5 (heuristic registry) is explicitly scaffolding — it wraps heuristics with metadata but removes no leniency and prevents no recurrence
  • D8 (RFC lifecycle CI) cannot catch the exact failure mode that produced Zone 2's orphan status (all checkboxes checked, scope silently narrowed)
  • _defect_from_reason_str (types.py:350-355) returns TreeDefect.OK for any unrecognized reason string, a silent misroute-to-TREE hole inside the single-writer itself

Root-cause fixes: D1 (garble funnel), D2 (block_text unification), D3 (single-writer enforcement, if amended), D4 (dispatch dedup), D10a (Arabic dead code), D10b (Zone-9 search text), D11 (verdict authority, if Release B validated).

Process mitigation only: D8 (RFC lifecycle CI), D9 (gap triage).

Q2: Which fixes are only mitigations that will require follow-up work?

  • D5 requires follow-up: each registered heuristic needs a dead-heuristic falsification test (a test that proves the heuristic can fire), otherwise the registry catalogs broken entries without noticing (garble.py:583 would have been catalogued as "active")
  • D8 requires follow-up: a zone-ownership manifest check to catch scope-narrowed closures (the exact failure mode that orphaned Zone 2)
  • D10a fixes one of 8 broken sites. The remaining 7 post-NFKC _infer_presentation_forms call sites need a successor deliverable
  • D11 concentrates all writes onto the RFC-037 D5 Postgres arbiter. If Release B's max-priority-wins upsert has bugs, D11 turns a 5-writer distributed problem into a single-point-of-failure problem

Q3: What gaps remain even if all 11 deliverables ship as currently scoped?

  1. Zone 2 majority-unowned. D10a fixes garble.py:583; 7 external post-NFKC call sites (pictures.py:272,393; recovery.py:125; indexer.py:514,1015,1041; garble.py:855) remain structurally broken with no deliverable

  3. D3 cannot express route overrides. 5 of 8 recovery.py mutations are intentional post-gate overrides. Implementing D3 as written would silently break RTL comparison, VLM-tesseract recovery, flat-prefer density heuristic, and landscape-reroute
  4. RFC-037 Release B unvalidated. D11 builds on a CAS arbiter that was never tested end-to-end
  5. D8 scope-narrowing blind spot. The CI gate parses checkbox state but cannot detect the RFC-040 failure mode where all boxes are checked and scope was silently narrowed
  6. _defect_from_reason_str OK-default hole. Not in any acceptance criteria. Any legacy-tuple caller with a novel reason string silently routes to TREE

The 6-item P0 plan above. Specifically: D10a + D10b + D4 + D1 + amended D3 + Zone 2 ownership assignment. 6. New Findings Not in RFC-041

The review uncovered three findings not mentioned in the audit report or RFC-041 artifacts:

Finding N1: D3 design gap — finalize_gate_and_route cannot express overrides

Severity: CRITICAL (blocks D3 implementation)

types.py:358-388: finalize_gate_and_route derives state.route purely as decide_route(first_defect, flat_routing_enabled) — a pure function of the existing defect with no override parameter. But 5 of the 6 state.route = sites in recovery.py are deliberate post-hoc overrides driven by orthogonal signals:

  • :602 — RTL flat-vs-tree text comparison
  • :658,:676,:694 — successful tesseract-raster recovery after VLM failure
  • :738 — content-density heuristic forces ok=False, route=FLAT even when gate said ok=True
  • :768 — landscape-picture-detection reroute

Impact if unaddressed: Implementing D3 as written would revert these overrides to gate-derived values, silently changing verdicts for RTL, VLM-recovery, flat-prefer, and landscape documents.

Fix: Extend finalize_gate_and_route with force_route: Route | None = None and force_ok: bool | None = None override parameters.

Finding N2: D11 async wrapper bug

Severity: HIGH (implementation will crash at runtime)

Task 3.5 in .agents/tasks/tasks-rfc041-recurring-defect-consolidation.md specifies wrapping _upsert_registry_row calls with asyncio.run() for sync callers. But the two callers in question — promotion_sweep.run_sweep (promotion_sweep.py:35) and preprocess_client.recompute_verdicts (preprocess_client.py:232) — are already async def functions that await other calls in the same scope.

Calling asyncio.run() inside a running event loop raises RuntimeError.

Fix: These callers should await _upsert_registry_row(...) directly.

Finding N3: D2 scope omits garble.py internal callers

Severity: MEDIUM (regression risk during D2 implementation)

RFC-041 D2 lists flat.py, tree_validation.py, helpers/rag.py as the files in scope. But garble.py itself calls _node_text_parts at :648 and :685, and _flat_block_primary_text at :780 — three internal consumers not in D2's declared file list.

When these accessors are replaced by block_text(purpose), garble.py's per-node table-content check (:692-695) needs re-validation to ensure garble scores don't shift.

Fix: Add helpers/garble.py to D2's reviewed file list and test surface.
