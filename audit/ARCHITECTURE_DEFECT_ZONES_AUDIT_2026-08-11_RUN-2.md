## Zone 1 — Verdict engine: 11-gate first-match cascade + a second engine that re-derives the same signals (critical, 12 bugs)

**Description.** `validate_tree` (`helpers.py:1387-1507`) is a fixed ladder of 11 early-return gates accreted in RFC order, emitting exactly ONE defect string. `classify_verdict` (`helpers.py:1677-1844`) receives that string but does not trust it: `TreeSignals.from_tree` (`helpers.py:1710`, defined `171-201`) independently re-computes garbled, garble_ratio, is_reordered, node_count, depth and max_leaf_ratio from the same tree, then ORs its own is_reordered with the passed reason (`1726`). Two engines, one tree, no consistency check. On top: ~10 env thresholds re-read per call (`VerdictThresholds.from_env`, `helpers.py:141-156`), a history dependency (`prior_verdict` widens `pass_max_leaf_ratio`, `1779-1780`), and a `_pass()` cap (`1745-1753`) that rewrites every promotion's reason after it was earned.

**Mechanism.**

1. **First-match-wins masking:** gate N returns, so gates N+1..11 never evaluate — defect co-occurrence is unobservable, and every new gate must be appended at the bottom with a comment begging it not to shadow its elders (`helpers.py:1426`, `1458-1459`, `1502`). The oldest, coarsest gates run first, so a garbled degenerate tree exits as `node_count<3` and the string-keyed OCR recovery never fires. Appending a gate is never additive: it changes which of two co-occurring defects a document reports → routing → verdict.
2. **Thresholds calibrated globally but validated locally:** a threshold tuned on one known-bad document silently reclassifies every unrelated document near that boundary.
3. **Dual derivation:** any fix in `validate_tree` without a mirror in `TreeSignals` produces a document whose stored gate reason and stored verdict disagree — the stored-vs-judged divergence the audits keep reporting.
4. **VERIFIED DEAD GATE:** gate 11 (`arabic_low_content_ratio`, `helpers.py:1503-1506`) tests `_is_garbled_blob(full_text, expected_script)` on `_flatten_tree_text(structure)`; gate 1 (`helpers.py:1400` → `_tree_is_garbled`, `1326-1332`) tests the same call OR `_has_sparse_mojibake` on the identical input, nothing mutating in between. Gate 1 is a strict superset → gate 11 unreachable, never once fired, hidden by the cascade.

**History (12):** (a) `node_count<3` masking garbling so OCR never escalates (وارد 597; obs #5330). (b) RFC-026 D5 had to reorder the cascade itself (obs #5338). (c) Run 13: new `low_content_density` gate simultaneously failed three previously-PASS unrelated large docs — "a systemic cause… rather than three independent extraction failures" (RUN-13). (d) Run 7: D10's 0.17→0.20 widening missed Reitlehrer (0.2571), contradicting RFC-023's "zero regressions" claim. (e) Run 9: RFC-025 hysteresis retune softened four zero-char Arabic docs FAIL/ERROR→MARGINAL with 0 blocks — "verdict-gate softening that hides real content loss" (obs #5327). (f) Run 8→9: GHV-TKV-Tarif byte-identical tree flipped PASS→MARGINAL from the retune alone (obs #5327/#5467). (g) RFC-014 D4 0.15→0.17 promoted سياسة حوكمة to PASS; Run 16 found 67% of its leaves severely RTL-garbled (obs #3977/#5627). (h) RFC-026 D0/D1 shipped 5 self-inflicted test regressions (obs #5356/#5397). (i) `image_enrichment_promoted` PASSed docs at 38–492 chars, violating Hard Rule 5 (obs #5327/#5467). (j) RFC-026 char floor "checks volume, not content validity" — وارد 597 still PASS on 3208 chars of barcode noise (RUN-10). (k) RFC-015 D2 closed half a two-bug pair; 3.5–6× stored/recomputed max_leaf_ratio discrepancy unaddressed (obs #4127/#4196). (l) unreachable gate 11 (this audit).

**Code:** `helpers.py:1387-1507`, `1400` vs `1503-1506` (dead gate), `1710`+`171-201` (re-derivation), `1716-1727` (GROUP-1 hard fails via `==`/`.startswith()` on the reason string), `1745-1753` (`_pass()` rewrite), `1759-1769` (image rescue above the max_leaf_ratio hard FAIL at `1774`), `1779-1780` (hysteresis), `1811-1812` (inspector cat_c widening), `141-156` (env re-reads).

## Zone 2 — OCR escalation vs per-picture enrichment: mutually-exclusive subsystems joined by a fragile marker-count contract (critical, 11 bugs)

**Description.** Page-level OCR escalation (`force_full_page_ocr`) and per-picture crop-OCR/VLM enrichment are structurally incompatible — forcing full-page OCR destroys the PictureItem segmentation enrichment consumes (documented verbatim at `client.py:978-981`). Yet they are gated by ONE flag, wired through an all-or-nothing ordinal count guard, and exchange output through an untyped `skipped_reason` string protocol that silently controls the verdict denominator.

**Mechanism.**

1. **Mutual exclusion:** winning the garble gate (force OCR) loses the image-enrichment PASS rescue and vice versa — any change to the OCR trigger silently re-routes documents between two subsystems with different verdict rules. `PRE_GARBLE_FORCE_OCR_ENABLED` defaults false precisely to avoid this (`client.py:982-984`), making the entire D3a probe (`client.py:941-976`) a log-only no-op on the default path.
2. **All-or-nothing count guard:** `splice_picture_text_for_tree` (`converters.py:2474-2483`) abandons EVERY picture's OCR text for the whole document if `md.count('<!-- image -->') != len(real_pics)`. Anything changing marker counts silently voids all recovered chart text. Both splices must exclude the fabricated `landscape_fallback_picture` entry by LITERAL STRING (`converters.py:2473`, `2513`).
3. **Destructive shared mutation:** `splice_figure_markers` pops `ocr_text` out of the shared PictureResult dicts (`converters.py:2552-2554`, invoked at `client.py:1816`); `_enrich_image_blocks` then reads `''` for the spliced subset (`client.py:771`); `compute_image_enrichment_ratio` (`helpers.py:1631-1649`) scores on ocr_text presence and drives the ≥0.8 PASS rescue. Whether a document PASSes depends on a mutation-order side effect three call sites away.
4. **Skip reasons as verdict input:** every extraction-side skip string removes the block from both numerator and denominator (`helpers.py:1640`), so tightening an extraction filter silently re-scores the document.

**History (11):** (a) 5-step Arabic cascade collapsing structure for 4 scanned Arabic PDFs (2026-07-27 audit). (b) D0 fabricating N duplicate PictureResults purely to satisfy the guard. (c) Per-picture OCR firing a second time during escalation ("Both OCR passes compete"). (d) RFC-017 P0a/P0b filters killing legitimate enrichment for docs 3 and 9. (e) Skips without `skipped_reason` leaving `<!-- image -->` verbatim in prose (Issue 4; RFC-022 B3 addendum). (f) OCR text moved to `block['ocr_text']`, structurally invisible to `content_class`. (g) Single `_OCR_ESCALATION` kill-switch gating both mechanisms. (h) D1 probe added because sub-60%-coverage charts were re-OCR'd at 300 DPI, garbling "2019 2020 2021" into "20l9 2O2O 202l". (i) 4,267→375 char table-doc drop misdiagnosed through three hypotheses (`role='table'` blocks carry no `text` key). (j) RFC-035 regressed BOTH `uae_numbers` orientations together (RUN-19). (k) MAX_FULLPAGE cap fires before the exemption, so Docling's region enumeration order decides which pages get OCR'd (`converters.py:2241-2248` vs `2269`).

**Code:** `client.py:978-984`, `941-976`; `converters.py:1581` vs `client.py:344` (verbatim duplicate `_OCR_ESCALATION` with a stale "Mirrors client.py:66" comment); `converters.py:2474-2483`, `2473`, `2513`, `2552-2554`; `client.py:762-782`, `1816`, `1934`; `helpers.py:1631-1649`, `1640`, `1759-1769`; `converters.py:2236-2248`, `2269`.

## Zone 3 — Six Arabic/RTL order deciders + 10-prong garble gate via 13 differently-shaped call sites (critical, 9 bugs)

**Description.** Arabic orientation is decided six separate times at four pipeline stages with four sampling strategies and five Arabic-ratio thresholds: `_detect_arabic_reversal` (`converters.py:110`), `_text_is_logical_order` (`1442`), `_heading_is_logical_order` (`1473`), `reconstruct_bidi_order` (`1497`), `_fix_residual_rtl_reversal` (`1552`); gate side `_tree_is_rtl_reversed` (`helpers.py:1335`) and `_check_bidi_coherence` (`helpers.py:1158`). Underneath, one 10-prong primitive `garble_prongs` (`helpers.py:1044-1113`) is called from 13 sites over blobs of incompatible shape with inconsistent `expected_script` threading.

**Mechanism.** (1) **No shared verdict:** extraction can decide "already logical" and the gate later decide "reversed" on the same bytes. `reconstruct_bidi_order` applies a document-level boolean to the body but judges each heading individually (`converters.py:1526` vs `1532-1538`) — a doc just under 0.15 gets headings flipped and body untouched, producing titles and text pointing opposite directions, then `_fix_residual_rtl_reversal` runs at a different threshold (per-line >0.5) and can re-reverse lines the first pass deliberately left alone. (2) **Successful repair suppresses the escalation detector:** a correct bidi repair removes exactly the presentation-form signature `garble_prongs` keys on (`helpers.py:1068-1076`) — benign when the repair was right, content-losing when it double-reversed. Prong semantics shift per caller: digit_ratio gated behind `len(blob)>500` (`1086`); raw-markdown callers dilute ratios with `#`/`|`/whitespace while tree callers don't, so flat and tree gates systematically disagree. **VERIFIED STILL-OPEN HOLE:** `converters.py:1746`, `converters.py:1844`, `helpers.py:1768` pass NO `expected_script`, unconditionally disabling the latin_gibberish prong (`helpers.py:1100-1102`) — `helpers.py:1768` is the `image_enrichment_promoted` rescue's own garble check.

(b) سياسة حوكمة 67% RTL-split leaves, stored PASS (obs #5627/#5639). (c) UN Human Rights doc PASS with 97% presentation-form glyphs (obs #4114). ## Zone 5 — `reason` as both diagnosis and routing command inside the ~1,300-line `index()` (critical, 8 bugs)

**Description.** `client.py:index()` (~840–2195) contains five `validate_tree` call sites, five recovery ladders, two branches that override a PASSING tree, both persistence paths and both `classify_verdict` call sites. Its central variable `reason` is simultaneously DIAGNOSIS and ROUTING TOKEN: recovery branches assign `reason = 'node_count<3'` (`client.py:1535, 1602, 1628, 1741, 1769, 1856`) purely to steer into the flat-routing whitelist, and `reason = 'garbling'` (`1827`) to mean "reject". **A typed `TreeDefect` StrEnum and exhaustiveness-asserted `REASON_POLICY` table exist (`helpers.py:63-120`) but are imported by nothing except `tests/test_zone1_reason_enum.py`** — production routing is a hand-maintained duplicate of literal string comparisons.

**Mechanism (all verified).** (1) **Persisted `verdict_reason` is a routing artefact:** RFC-029 D1 flat-prefer (`1721-1741`) and RFC-035 D2 landscape re-route (`1760-1769`) both take a PASSING tree and force `ok=False; reason='node_count<3'` to reuse the flat branch's persistence code — the doc is stored describing a defect it doesn't have and its tree artifact is never written. (2) **The rescue variable is itself clobbered:** `original_reason` captured at `1247` ("before any recovery retry overwrites reason") — yet every retry block reassigns it (`1346, 1492, 1580, 1702`), and the RFC-030 D1 atomic revert (`1446-1455`) restores six variables and OMITS it. With `retry_wins = False` whenever `post_retry_chars < pre_retry_chars` (`1377`), a clean-but-shorter retry leaves `reason` reverted to `'garbling'` while `original_reason` is `''` — and `client.py:2121` passes `original_reason or None` into `classify_verdict`, so the GROUP-1 garbling hard-fail and the flat garble-by-default protection (`1825`) silently evaporate — the exact protection RFC-025 D2 built the variable for. (3) **New defects get no path:** recovery gated by literal tuples (`1266, 1548, 1590`), persistence by `reason in ('node_count<3','depth<2','rtl_reversal')` (`1780`); every gate added since falls to the terminal tuple (`2066`) or the persist-FAIL escape (`2078`) — adding a diagnosis is an implicit decision to hard-fail documents.

## Zone 6 — Verdict persistence: five writers, lost-update sidecar merge, verdict stored apart from its artifact (high, 8 bugs)

**Description.** The verdict is authored by five independent writers with no shared entry point — `client.py:2175` (ingest, full signals), `storage.save_flat_doc:287` (implicit), `registry_backfill._enrich_one:202` and `_heal_one:339` (no verdict at all), `promotion_sweep.py:105` and `preprocess_client.py:305` (recomputed with wrong or absent inputs) — all funneling into `save_doc_meta` (`storage.py:508`), a read-merge-write with no ETag/CAS. **Mechanism.** (1) **Lost update by construction:** reconcile cron, orphan healer, completing ingest, sweep and recompute script all race on the same key; `_confirm_write_visible` (`storage.py:44`) proves visibility, not absence of clobber — RFC-034 D18's barrier fixed a symptom, which is why the race class recurred. (2) **Two-phase non-atomic artifact write read as corruption:** tree docs write `processed/<id>.json` (`client.py:2102`) then `meta.json` (`2175`); `registry_backfill` classifies the in-between state as an ORPHAN and "repairs" it from a source that cannot contain a verdict. (3) **Filter and writer disagree about where the verdict lives:** `read_registry_fields` (`storage.py:646-649`) copies verdict only `if vf in data`; the tree payload (`client.py:2105-2113`) has no verdict key, so every fresh tree doc upserts `verdict=''`; read paths filter `WHERE verdict != 'FAIL'` (`registry.py:296, 379, 391, 511`) and `'' != 'FAIL'`, so a FAIL tree doc is fully queryable until the reconcile cron catches up. ## Simplification proposals (top 5 zones, code-simplifier + Opus, source-verified)

### Zone 1 — Single-derivation signals + declarative gate table (~3.5–4.5d, helpers.py ≈ −100 net)

Derive every tree signal exactly once into `TreeSignals` (one writer per field); turn `validate_tree`'s 11 hand-ordered early returns into a declarative rule table evaluated **exhaustively** over that snapshot — reporting the full set of firing defects plus one priority-selected primary, so appending a rule can no longer change an existing document's verdict. `classify_verdict` consumes the `TreeGateResult` instead of re-deriving signals and string-matching the reason.

Steps: S0 extend `TreeSignals` with the fields `validate_tree` computes inline (behavior-identical). S1 replace the 11 `if…return` blocks with a `_GATES` tuple `(TreeDefect, predicate, detail)` in today's priority order; `defect = defects[0]` stays byte-identical. ## Cross-cutting themes (17, from 40 mined causal chains)

1. The Arabic/RTL garble-gate is the single most persistent fight-between-mechanisms locus — the expected_script gap opens and closes across ≥6 runs for the same documents, stored gate verdict and audit-judge verdict diverging nearly every run.
2. Nearly every gate-hardening fix is calibrated against one or a few known-bad documents, then either misses jitter in an unrelated doc or simultaneously fails several unrelated docs — thresholds are consistently too narrowly validated before landing.
3. OCR-forcing side effects recur as a category: forced full-page OCR changes Docling's PictureItem/TextItem classification, which breaks marker-count splice guards downstream — the same structural dependency resurfacing under different RFC numbers.
4. A large fraction of apparent Runs-15–19 "regressions" are audit/measurement artifacts (dispatched figures not matching live MinIO state, accounting differences, doc-identity mixups). RFC-025 D4 catches them; the dispatching harness was never fixed, so the false-signal class recurs.
5. The judge scores holistically, so content-loss regressions get graded PASS (missing content reclassified as a logo/decorative) — the audit's own verdict is not a reliable single regression signal without char/node-count cross-checks.
6. Fixes scoped to one document or failure mode land without regression testing against the sibling set sharing the code path (RFC-035 landscape+portrait; RFC-034 D18 barrier vs polling window).
7. Persistence-timing races recur across Runs 15/16/18/19 on different documents each time despite D18 — the barrier addressed a symptom, not the ordering defect between ingest-write and the scorer's polling window.
8. GHV-TKV-Tarif's un-wired `_segment_table_nodes` has been documented-unfixed across essentially the whole 10+ run history — some early-identified root causes are simply never triaged.
9. Single kill-switches gate multiple structurally-different mechanisms, so toggling one for a targeted fix silently disables or over-empowers the other.
10. Fixes verified locally routinely fail to reach the code that serves production (working-tree guard never committed, uncommitted D1 probe, drifting duplicated threshold) — no provenance trail proving which code version actually ran.
11. Detection heuristics built from two independently-scoped sub-components whose scopes fail to cover each other produce "null detectors" that look safe (0 violations) while never firing.
12. Signals computed correctly at one stage routinely have no wired consumer downstream (ingest verdict, inspector classification, OCR text) — dead-ended in logs or unused columns.
13. Availability fallbacks (AGPL fallthrough, non-fatal dual-write swallow, zero-failure backfill flag) conflate "degraded but technically succeeded" with "safe".
14. Verdict-gate hardening repeatedly trades one failure mode for another in the same change or shortly after.
15. Detection and remediation are chronically decoupled: documents correctly diagnosed yet permanently stuck unrecovered across runs because the recovery hook is missing, mis-ordered, or scoped to a different path.
16. Fixes to one extraction path are left unported to the parallel path (RFC-026 D2 rotation: docling only) — complete in the task tracker, incomplete in code.
17. Self-reported quality numbers diverge from ground truth at every layer (fabricated corpus report, harness defaulting to ERROR, miscounted tests) — a recurring reporting-integrity gap relearned repeatedly rather than structurally fixed.
