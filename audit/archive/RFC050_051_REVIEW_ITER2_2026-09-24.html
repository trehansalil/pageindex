Findings

Finding 1 (CRITICAL): D5 Recovery Parallelization Is Architecturally Infeasible

Source: recovery-deep-dive agent

Issue: All 8 recovery methods in RecoveryMixin (client/recovery.py) mutate the same shared ExtractionState object. The GateSpec dispatch loop in index() (L2613-2660) iterates in severity order — each method's eligibility depends on state left by prior methods (e.g., if garble OCR fires and sets state.ok = True, subsequent methods skip). Sequential ordering is a correctness invariant, not a performance bottleneck.

Evidence: 8 methods analyzed: _recover_garble_ocr, _recover_low_content_ocr, _recover_image_dominant_ocr, _recover_rtl_repair, _recover_rtl_flat_compare, _recover_vlm_fallback, _recover_flat_prefer, _recover_landscape_reroute. All write to state.result, state.ok, state.route, state.first_defect via shared finalize_gate_and_route.

Resolution: User chose to redefine D5 as "optimize individual methods" (profile slowest, reduce redundant reconversions, cache intermediate results). Reclassified P1→P2. Effort revised 6h→4-6h. All 3 triad files amended.

Finding 2 (CRITICAL): D3 save_raw Insertion Point Is Architecturally Wrong

Source: save-raw-integration-point agent

Issue: RFC stated "AFTER successful PDF extraction AND before _run_stages" but _run_stages runs inside each converter function (e.g., pdf_to_markdown_docling at pipeline.py:714), NOT in _convert_to_tree. By the time state.md_content is set in _convert_to_tree, stages have already run.

Evidence: _run_stages called at pipeline.py:714 inside pdf_to_markdown_docling. state.md_content set at multiple convergence points (L1213, L1244, L1255, L1430, L1551, L1562, L1712, L1716). Additional concern: doc_id may not be available at the convergence point — available via state.result.get("doc_id", filename).

Resolution: User chose "post-stages at convergence point" (~L1728, before prepare_tree/validate_tree). Single insertion point covers all 6+ converter paths. All 3 triad files amended with corrected insertion point and doc_id access pattern.

Finding 3 (HIGH): RFC-051 Scripts Have Active Test References

Source: script-reference-check agent

Issue: 2 of 4 "dead" scripts have active test coverage that would break on deletion:

  • scripts/ocr_spike_eval.py: tests/test_ocr_fallback.py (6 lines), tests/TEST_INDEX.yaml, docker-compose.yml
  • scripts/facade_surface_measure.py: tests/test_source_invariants.py (import + invariant test for RFC-045 pins)

Resolution: User chose "delete scripts + remove test coverage". New task 1.2 added to RFC-051 tasks with explicit file:line references for all cleanup targets. D1 effort revised 1h→2-3h. Total RFC-051 effort revised 10h→11-12h.

Finding 4 (NOTABLE): hash_cache_migrate.py Has Gate Whitelist Entries

Source: script-reference-check agent

Issue: src/pageindex_mcp/hash_cache_migrate.py has zero Python callers but 6 grep whitelist entries in scripts/gates/static.sh (lines 175, 186, 198, 202, 216, 222). Deletion is safe but leaves dead whitelist comments.

Resolution: Cleanup included in new task 1.2 — remove whitelist entries in same commit as script deletion.
