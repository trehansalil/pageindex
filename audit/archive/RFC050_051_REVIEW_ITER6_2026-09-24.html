RFC-050 & RFC-051 — Iteration 6 Review Report (focus: D4 --from-raw)

Date: 2026-09-24  |  Iteration: 6 of rfc-iterate  |  Reviewer agents: D4 claim validator, D4 feasibility reviewer, D4 lead analyst  |  Coordinator verification: source checked via codebase-memory

Summary: D4 as written could not be built. The cached .extracted.md has already been through normalization and recovery, so "re-run all normalization stages" would apply them twice, and two of the three stages need the PDF. R4 AC1's precondition, "hash unchanged", is exactly the case index() dedups away. A re-persist would mint a second doc_id. The HTTP upload route has no way to name a cached document. The state-reconstruction task listed four fields that do not exist.

Per the user, D4 is now a command-line dry-run replay for stored documents and rejected (quarantined) ones:
  • It keeps a state file for both stored and quarantined documents.
  • Recovery is on for stored documents, with --no-recovery to skip it.
  • It writes nothing, enforced by a write barrier.
The coordinator found that the verdict is computed inside the save methods, so a dry run has to block writes rather than return early. The same check found a P0 bug in D3: state.md_content can be None.

G1 no longer counts D4, and Task 1.5 adds an extraction / tree-build timing split. RFC-050's effort estimate rises from 25.5-33.5h to 31-35h. RFC-051 is unchanged: its D4 is an unrelated deliverable (decision-points YAML).

Coordinator Verification (new this iteration)

  • The verdict lives inside the save methods. compute_verdict is called at client/indexer.py:2316 (_persist_tree_result, inspector_class=pdf_classification["pdf_type"]) and :2025 (_persist_flat_result, which also runs the RFC-047 Surya density fallback). Returning before the save step would skip the verdict, so the design uses a write barrier at the MinIO, Redis and registry clients in the replay child (Task 5.2b, Property 4a, Risk 6).
  • The quarantine prefix is confined to one file. check_quarantine_prefix_confined (scripts/gates/source_invariants.py:2039-2064) allows the "quarantine/" literal only in storage/documents.py. The reader goes there, and a new gate check limits its callers to preprocess_client.py.
  • Current quarantine keys. _erase_quarantine and erase_quarantine each remove exactly .json and .meta.json today (storage/documents.py:612-629, :945-966). After D3 there will be four keys.
  • Some PDFs build their tree without markdown. When every converter fails, the tree comes from _run_page_index_retrying(file_path), an LLM pass over the PDF, and there is no markdown. Those documents can't be replayed and return no_raw_cache.
  • RtlDecision is a frozen dataclass (script.py:668-682), so it can be serialised.
