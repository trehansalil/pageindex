RFC-050 & RFC-051 — Iteration 7 Review Report (full review)

Date: 2026-09-24  |  Iteration: 7 of rfc-iterate  |  Reviewer agents: claim checker (V7), feasibility reviewer (I7), lead analyst (L7)  |  Amend agents: one each for the RFC-050 and RFC-051 document sets

Summary: The Iteration 6 D4 write barrier could not work, for two reasons:
  • save_doc and save_flat_doc check each write with stat_object (_confirm_write_visible, documents.py:97-108 and :162-173). A barrier that swallows writes therefore raises PersistenceNotVisibleError.
  • Registry writes happen only in the parent process (preprocess_client.py:201, job.py:392), so wrapping the child's registry client does nothing.
RFC-051 D4 had two faults:
  • It depended on a get_decision_point() API that does not exist.
  • It set a ≤50-line module cap that cannot be met.
Both RFCs were also missing interactions with the test-budget ratchet, the closed decision-event registry and FROZEN_SURFACE. The user's four decisions below settled all of this, and both document sets have been amended.
