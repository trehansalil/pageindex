## Overview

This plan implements eight of the nine RFC-027 fix dimensions (D0-D7) across four batches, plus a documentation-only correction (D8) — Run 10 is the first run after RFC-026 gate-hardening landed, and the resulting FAIL count (0 → 10) is overwhelmingly a *correct* surfacing of pre-existing extraction defects that RFC-026's D0/D1 floors now expose rather than soft-land. Batch 0 ([Task 1](#1-batch-0--independent-small-fixes-d0-d5-d6-d8)) lands the four independent, low-cross-dependency fixes the RFC itself groups together — [D0](../rfcs/027-run10-extraction-gate-and-arabic-recovery.md#d0----split-_flat_block_text-to-exclude-enrichment-metadata-from-verdict-char-counts) (split `_flat_block_text` so verdict char counts exclude enrichment metadata), [D5](../rfcs/027-run10-extraction-gate-and-arabic-recovery.md#d5----relax-small-doc-leaf-ratio-threshold-for-very-small-trees) (small-doc leaf-ratio dispensation), [D6](../rfcs/027-run10-extraction-gate-and-arabic-recovery.md#d6----deduplicate-identical-adjacent-image-markers-from-docling-standalone-image-export) (adjacent image-marker dedup), and [D8](../rfcs/027-run10-extraction-gate-and-arabic-recovery.md#d8----correct-run-10-audit-report-landscapeportrait-twin-scorecard-and-d4-verification-gap) (audit report correction, documentation only). Batch 1 ([Task 2](#2-batch-1--verdict-gate-garble-hardening--ocr-escalation-d1-d2)) lands [D1](../rfcs/027-run10-extraction-gate-and-arabic-recovery.md#d1----wire-garble-detection-into-image_enrichment_promoted-branch-and-reorder-d3b-check-post-splice) (garble detection wired into the `image_enrichment_promoted` branch, plus post-splice D3B re-check — depends on D0's split landing first so char counts are accurate before garble-checking) and [D2](../rfcs/027-run10-extraction-gate-and-arabic-recovery.md#d2----extend-ocr-escalation-to-low-content-and-garbled-arabic-pdfs) (low-content OCR escalation for zero/near-zero-content Arabic PDFs, the RFC's single highest-severity item). Batch 2 ([Task 3](#3-batch-2--arabic-extraction-improvements-d3-d4)) lands [D3](../rfcs/027-run10-extraction-gate-and-arabic-recovery.md#d3----add-rtl-reversal-detection-to-validate_tree-fix-_text_is_logical_order-and-wire-repair-first-flow) (RTL reversal detection with a repair-first flow via `reconstruct_bidi_order`) and [D4](../rfcs/027-run10-extraction-gate-and-arabic-recovery.md#d4----inject-arabic-structural-headings-for-non-heading-lines) (Arabic structural heading injection, sequenced after D2 per the RFC's own rationale — OCR-recovered raw content is what D4's heading injection then structures). Batch 3 ([Task 4](#4-batch-3--large-document-timeout-guard-d7)) lands [D7](../rfcs/027-run10-extraction-gate-and-arabic-recovery.md#d7----add-page-count-guard-for-large-document-docling-timeout-chunked-docling-route) (page-count guard + chunked-Docling fallback for oversized PDFs), kept isolated as the RFC's largest single change (4 files) and operationally independent of the verdict-gate/Arabic-recovery work in Batches 0-2. Per explicit user directive, **no task in this plan performs ingestion, reingestion, or corpus verification** — those steps belong to the corpus quality cycle, which runs separately after this plan lands. Every code task ends at a `uv run pytest` unit/integration-boundary test.

## Notes

- Per explicit user directive: this plan contains **no ingestion, reingestion, or "verify with corpus" tasks**. The corpus quality cycle (separate skill/process) handles ingestion and scoring after this plan's code changes land; do not add such a step to any batch or checkpoint here.
- [Task 1.1](#11-split-flat-block-text)'s D0 split is a hard prerequisite for [Task 2.1](#21-garble-detection-in-image-enrichment-promoted)'s D1 garble check — the garble detector must operate on accurate (non-enrichment-inflated) char counts, or it inherits the same false-PASS risk D0 fixes.
- [Task 3.3](#33-repair-first-flow-wiring)'s repair-first ordering is load-bearing: `rtl_reversal` must never hard-FAIL a document before `reconstruct_bidi_order` has been attempted, per the RFC's explicit framing that this prevents FAILing a document the bidi repair can actually fix. This is a stricter ordering requirement than a typical gate check and should be reviewed carefully at [Checkpoint 3.6](#36-checkpoint--batch-2).
- [Task 4.1](#41-max-docling-pages-config)/[4.2](#42-chunked-docling-primary-path)/[4.3](#43-text-layer-fallback) must not introduce `pymupdf4llm` as a fallback under any code path — per [CLAUDE.md Hard Rule 4](../../CLAUDE.md#hard-rules) and the RFC's own explicit licensing-constraint note, PyPDF2 (already a dependency, MIT-licensed) is the only fallback extraction library used in this RFC.
- [Task 1.2](#12-small-doc-leaf-ratio-dispensation)'s D5 threshold relaxation is scoped strictly to `node_count <= 5`; do not generalize the 0.40 ceiling to larger trees without a corpus-wide impact check, per the RFC's stated risk of promoting genuinely degenerate 6-10 node stub trees.
- [Task 1.3](#13-dedup-adjacent-image-markers)'s D6 dedup regex must only collapse markers with a whitespace-only gap — any test or future edit that widens the regex to strip markers with genuine intervening content would silently break the RFC-018 D0 multi-region `PictureResult` design; this is called out explicitly because it is easy to over-generalize a "just collapse all consecutive markers" fix.
- Every fix in this plan that gates an existing behavior change ships with a review-time note rather than a new env-var toggle by default, EXCEPT [Task 4.1](#41-max-docling-pages-config)'s `MAX_DOCLING_PAGES`, which is explicitly an env-configurable threshold per the RFC — apply the project's existing `int(os.environ.get(...))` pattern already used for `MIN_IMAGE_PROMOTED_CHARS` (RFC-026) and `MIN_FLAT_PROMOTION_CHARS`.
- Tests in [Task 1.5](#15-unit-tests-batch-0), [Task 2.4](#24-unit-tests-batch-1), [Task 3.5](#35-unit-tests-batch-2), and [Task 4.4](#44-unit-tests-batch-3) are required, not optional, given the [CLAUDE.md Hard Rule 5](../../CLAUDE.md#hard-rules) quality-gate implications of D0-D5 and D7 — do not skip them for a faster landing.
