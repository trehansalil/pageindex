## Overview

This plan implements RFC-028's eight fix dimensions (D0-D7) across three batches. Run 11 is the first run after RFC-027 landed: FAIL count dropped 10 → 4 and five previously zero-content Arabic PDFs now yield real text, but all five land at MARGINAL with flat/depth-0 trees because of two Arabic-heading-injection bugs, and Arabic garble detection has two blind spots (presentation-forms glyphs, RTL-reversal vocabulary gaps). Batch 1 ([Task 1](#1-batch-1--critical-bugs-with-no-inter-dependencies-d0-d1-d2)) lands the three RFC-scoped Batch-1 fixes the RFC itself groups together as having no cross-dependencies — [D0](../rfcs/028-run11-arabic-recovery-and-timeout-wiring.md#d0----wire-dynamic-timeout-into-worker-subprocess) (wire the dead-code `chunked_docling_timeout_s` into `worker.py` and raise the per-chunk/JOB_TIMEOUT constants, unblocking world-stats-pocketbook's 3-consecutive-run ERROR), [D1](../rfcs/028-run11-arabic-recovery-and-timeout-wiring.md#d1----fix-arabic-structural-heading-injection-prev_blank--char-limit) (remove the `prev_blank` guard and raise the 60-char title limit in `_inject_arabic_structural_headings`, unblocking 5+ Arabic docs stuck at depth-0), and [D2](../rfcs/028-run11-arabic-recovery-and-timeout-wiring.md#d2----arabic-presentation-forms-garble-detection) (add a Presentation-Forms ratio check to `_is_garbled_blob`, catching the single largest false-PASS in the corpus by char volume). Batch 2 ([Task 2](#2-batch-2--arabic-recovery-hardening-d3-d4-d5)) lands [D3](../rfcs/028-run11-arabic-recovery-and-timeout-wiring.md#d3----expand-rtl-reversal-detection-vocabulary) (expand `_AR_COMMON_WORDS` plus a vocabulary-independent morphological reversal check), [D4](../rfcs/028-run11-arabic-recovery-and-timeout-wiring.md#d4----fix-3-ocr-retry-keep-best-instead-of-unconditional-overwrite) (snapshot-and-keep-best instead of unconditional overwrite in the low-content OCR retry), and [D5](../rfcs/028-run11-arabic-recovery-and-timeout-wiring.md#d5----fix-ocr-language-detection-source-in-_recover_picture_results) (derive OCR language from filename, not near-empty `md`, in `_recover_picture_results`, plus de-duplicate spliced fragments) — grouped per the RFC's own Batch 2 rationale as combined Arabic-doc regression testing that should run after Batch 1's D1 heading fixes are in place. Batch 3 ([Task 3](#3-batch-3--lower-severity-improvements-d6-d7)) lands [D6](../rfcs/028-run11-arabic-recovery-and-timeout-wiring.md#d6----gate-vs-judge-alignment-for-image-markers-in-hierarchical-docs) (audit-judge prompt alignment — no source-code change, `classify_verdict` is already correct) and [D7](../rfcs/028-run11-arabic-recovery-and-timeout-wiring.md#d7----add-standalone-roman-numeral-ordinal-splitting) (standalone Roman-numeral ordinal splitting in `_OVERSIZED_ORDINAL_RE`), both independent of the earlier batches. Per explicit user directive, **no task in this plan performs ingestion, reingestion, or corpus verification** — those steps belong to the corpus quality cycle, which runs separately after this plan lands. Every code task ends at a `uv run pytest` unit-test boundary.

Treat this as closing that gap, not as new scope; verify at [Checkpoint 1.5](#15-checkpoint--batch-1) that the RFC-027 D7 tests (`tests/test_rfc027_d7.py`) still pass unchanged.
- [Task 1.1](#11-wire-dynamic-timeout-into-worker)'s `JOB_TIMEOUT` raise (1800 → 3630) is worker-level in arq, not per-job — it affects worst-case slot occupancy for **every** job, not just large chunked PDFs. This is an accepted trade-off per the RFC (world-stats has failed 3 consecutive runs); do not attempt to scope it per-job, arq does not support that.
- [Task 1.2](#12-fix-arabic-heading-injection)'s `prev_blank` removal is safe only because promotion stays gated on the marker regex matching at line **start** — do not weaken that anchor when landing this fix, or mid-paragraph article references will be over-promoted to false headings.
- [Task 2.1](#21-expand-rtl-reversal-vocabulary)'s cross-module word-list move (`converters.py` → `helpers.py`, or an import) must not introduce a circular import between the two modules; verify with `uv run python -c "import pageindex_mcp.converters, pageindex_mcp.helpers"` after landing.
- [Task 2.2](#22-ocr-retry-keep-best)'s keep-best comparison uses `total_chars` as the primary signal and `_is_garbled_blob` as a secondary tie-break — do not invert this priority; a shorter-but-clean result should only win over a longer-but-garbled one when char counts are close, not whenever the pre-retry result happens to be non-garbled.
