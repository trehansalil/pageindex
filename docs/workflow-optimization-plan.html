Five Optimization Strategies

Obsidian Strategy 1: Obsidian as the Structured Data Bus

Problem: Each workflow writes markdown reports that the next workflow re-parses with LLM agents (2 haiku agents per parse).
Solution: zone-triage already writes Obsidian notes with YAML frontmatter. Use get_frontmatter() to read structured data directly — zero tokens, no agent needed. Write all audit outputs as Obsidian notes with typed frontmatter (severity, bug_count, status, key_files as arrays).
Saves: 2–4 parse agents per workflow invocation. Eliminates the "LLM as JSON parser" anti-pattern.

CBM Strategy 2: Replace File-Reading Miners with Graph Queries

Problem: arch-bug-pattern-audit spawns N+M haiku agents to Read RFC/audit files and extract chains. Each agent reads full files sequentially.
Solution: Use Obsidian search_notes to find all RFC/audit notes by tag, then read_multiple_notes to batch-read. One sonnet agent processes all inputs in a single pass instead of N+M haiku agents in parallel.
Saves: 6–10 miner agents. Single-agent extraction produces pre-deduplicated chains, eliminating the merge phase entirely.

CBM + Serena Strategy 3: Cache Architecture Maps

Problem: arch-bug-pattern-audit rediscovers the full architecture every run — 1 sonnet for discovery + 4–8 sonnet explorers + 1 sonnet merger = 6–10 agents.
Solution: One sonnet agent calls get_architecture() + search_graph() + trace_path() + Serena LSP to build a unified code map. Cache it in Obsidian (audit/architecture-map.md). On re-runs, call detect_changes() — if clean, read the cached map. Only re-explore changed subsystems.
Saves: 5–9 agents on re-runs (first run saves 4–8). Architecture exploration becomes incremental, not full-scan.

Strategy 4: Flatten Sub-Workflow Cascade

Problem: zone-post-verify calls 3 sub-workflows (arch-bug-pattern-audit, zone-delta-analysis, audit-reconcile), each spawning their own agent fleet. Total: 34–41 agents. Each sub-workflow agent independently loads ToolSearch schemas + reads dispatch-context.
Solution: Inline the essential work. The re-audit returns structured JSON; the delta is a JSON diff (no file parsing needed); wiring checks are MCP queries. No sub-workflow boundary needed.
Saves: Eliminates ~20 agents from sub-workflow overhead. Removes ToolSearch + dispatch-context tax multiplied across 30+ agents.

Strategy 5: Model Tier Rightsizing

Problem: 5 opus agents for simplification proposals (text-only, no code edits). Opus for diff computation on pre-structured data. Sonnet for template-fill report writing.
Solution: Simplification proposals → 1 sonnet agent (all zones in one prompt, text output). Diff → sonnet (structured JSON in, structured JSON out). Report writing → haiku (template fill with data injection).
Saves: 4 opus calls per arch-bug-pattern-audit run. 2 opus calls per zone-delta-analysis. Opus reserved solely for the synthesis phase where reasoning depth matters.
