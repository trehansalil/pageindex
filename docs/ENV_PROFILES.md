# Local / remote toggles

One command decides where everything points:

```bash
make env                      # the default: remote MinIO, remote Docling
make env PROFILE=local        # everything against docker-compose
make env PROFILE=hybrid       # compose infra, Scaleway Docling
```

`make env` resolves the toggles into **`.env.active`**, and the server, the
worker, `docker compose`, and `scripts/remote_ingest_test.py` all read that one
file. Nothing else needs to change when you switch.

```
.env                 secrets + app tunables (LLM keys, tokens) — the only place secrets live
env/local.env        the "local" side  (docker-compose addresses; committed, no real secrets)
env/remote.env       the "remote" side (cluster addresses + credentials; generated, gitignored)
env/profile.env      your persisted toggle choices (optional, gitignored)
        │
        ▼  scripts/env_profile.sh
.env.active          resolved — mode 600, gitignored, regenerated by `make env`
```

## The toggles

| Toggle | Values | Default | Controls |
|---|---|---|---|
| `PROFILE` | `remote` · `local` · `hybrid` | `remote` | sets the defaults for everything below |
| `MINIO` | `remote` · `local` | from `PROFILE` | `MINIO_ENDPOINT`, credentials, presign host |
| `REDIS` | `remote` · `local` | from `PROFILE` | `REDIS_URL` |
| `POSTGRES` | `remote` · `local` | from `PROFILE` | `POSTGRES_DSN` |
| `DOCLING` | `remote` · `local` | `remote` | `DOCLING_SERVICE_URL` + bearer token |
| `APP` | `host` · `compose` | `host` | whether addresses are host-side or compose-network |
| `MINIO_ACCESS` | `auto` · `cluster` · `public` | `auto` | which address for remote MinIO |

Set them on the make command line, export them as `PI_*` in your shell, or
persist them in `env/profile.env`:

```bash
make ingest PROFILE=local          # one-off
export PI_MINIO=remote             # for this shell
printf 'PI_PROFILE=hybrid\n' > env/profile.env    # sticky
```

Per-invocation beats the shell, which beats `env/profile.env`. Check what you
are about to get without writing anything:

```bash
make env-show PROFILE=hybrid
```

## Remote MinIO from anywhere

Remote MinIO has two addresses, and which one is right depends on where you are
sitting — which is exactly what `MINIO_ACCESS=auto` (the default) figures out:

- **cluster** — the k3s ClusterIP (`10.43.x.x:9000`). Fast, plaintext, and only
  routable *on* the k3s node.
- **public** — an HTTPS host reachable from anywhere, including your laptop.

`auto` probes the ClusterIP with a 2-second TCP connect and falls back to the
public host, so `make ingest` does the right thing on the server and off it.
Force either one with `MINIO_ACCESS=cluster` / `MINIO_ACCESS=public`. Both modes
support every S3 operation — the public one just carries a route prefix (see
below).

Generate the remote side **on the k3s node** (it needs `kubectl`), then copy the
file to wherever else you test from:

```bash
make env-remote                              # -> env/remote.env
scp env/remote.env laptop:~/pageindex/env/   # laptop then uses MINIO_ACCESS=auto -> public
```

Rerun `make env-remote` after a Postgres pod restart — that service is headless,
so the DSN points at a pod IP that changes.

### How presigning works over the public route

MinIO's public route is `infra.saliltrehan.com/minio/…`, served behind a Traefik
**StripPrefix** middleware. That prefix is *why* presigning works, not an
obstacle to it: Traefik removes `/minio` before MinIO sees the request, so MinIO
verifies the signature against `/<bucket>/<key>` — exactly the path the SDK
signs. The prefix is therefore spliced in **after** signing:

```
sign   ->  https://infra.saliltrehan.com/pageindex/uploads/a.pdf?X-Amz-…
splice ->  https://infra.saliltrehan.com/minio/pageindex/uploads/a.pdf?X-Amz-…
strip  ->  MinIO receives /pageindex/uploads/a.pdf   ✓ signature verifies
```

`MINIO_PRESIGN_PATH_PREFIX` (default `/minio`, set from
`PI_REMOTE_MINIO_PRESIGN_PATH_PREFIX`) drives the splice, in
`storage._apply_route_prefix`. Verified live against Traefik:

| Request | Result |
|---|---|
| signed path as the SDK emits it | `404` — Traefik has no `/pageindex` route |
| same signature, `/minio` spliced in | `200` |
| no signature at all | `403 AccessDenied` from MinIO |

So the route is not open access: every request needs a valid SigV4 signature over
host + path + query, presigned URLs expire in 15 minutes, and the bucket carries
no anonymous policy.

### Direct S3 over the same route

*Direct* S3 calls (`bucket_exists`, `list_objects`, `put_object`) take the same
route, so no tunnel or port-forward is needed. The prefix cannot go on the
client — the SDK refuses it:

```
Minio("infra.saliltrehan.com/minio", …)  ->  ValueError: path in endpoint is not allowed
```

So it is applied one layer down, in the HTTP client
(`src/pageindex_mcp/minio_client.py`): SigV4 signs `/<bucket>/<key>`,
`PrefixedPoolManager` rewrites the wire URL to `/minio/<bucket>/<key>`, Traefik
strips it back off, MinIO verifies exactly what was signed. Same trick as the
presign splice, applied to every verb instead of just GET.

`MINIO_PATH_PREFIX` drives it, and `make env` sets it automatically whenever
remote MinIO resolves to the public host:

```bash
make env MINIO_ACCESS=public
#   minio     remote  infra.saliltrehan.com/minio   [public]
```

Verified with a full `make ingest` (7 docx + 1 PDF) addressed entirely as
`infra.saliltrehan.com/minio` — staging, tree writes and artifact verification
all over the public route.

## Combinations that do not work

`make env` warns about these rather than letting you discover them 20 minutes
into a run:

| Combination | Why it breaks |
|---|---|
| remote Docling + local MinIO | Scaleway cannot fetch a presigned URL pointing at your localhost. PDFs/images fail; other formats fine. |
| remote Docling + remote MinIO, no public endpoint | Same reason — the presigned URL names a ClusterIP. |
| local Docling + remote MinIO over the ClusterIP | The container has to reach `10.43.x.x:9000`, which it generally cannot off the node. |

## Typical setups

```bash
# On the server, against shared infra (the default)
make env && make up && make preflight && make ingest

# Laptop, fully offline against compose
make env PROFILE=local
make compose-infra && make compose-docling
make up && make preflight

# Laptop, compose infra but the real Scaleway Docling
make env PROFILE=hybrid       # warns: PDFs will fail, see the table above

# Everything in containers, pointed at the shared cluster
make env PROFILE=remote APP=compose MINIO_ACCESS=public
make compose-app
```

`APP=compose` switches the local addresses from `localhost` to compose service
names (`minio:9000`, `redis:6379`, `postgres:5432`) so containers resolve each
other. `docker-compose.yml` reads `.env.active` via `--env-file`, and its
`environment:` blocks are `${VAR:-default}` rather than hardcoded — otherwise
the toggles would stop at the container boundary.

## Variables the toggles do not set

`make env` writes the connection settings. These three are left to you, because
they depend on the deployment rather than on which side of the local/remote
toggle you are on.

| Variable | Default | What it does |
|---|---|---|
| `PAGEINDEX_WORKER_MAX_JOBS` | `1` | arq worker concurrency. See the warning below. |
| `MINIO_REGION` | *(empty)* | Signing region. Empty means the SDK discovers it. Set it only if your MinIO/S3 is configured with a non-default region — pinning the wrong one makes every request fail to authenticate. |
| `MINIO_PATH_PREFIX` | *(empty)* | Route prefix for direct S3 calls. `make env` sets this for you when remote MinIO is reached over the public route; see [How presigning works](#how-presigning-works-over-the-public-route). |

### `PAGEINDEX_WORKER_MAX_JOBS` — only raise it against remote Docling

The worker defaults to **one job in flight**. A single Docling index can peak at
several GiB, so letting two heavy jobs stack doubles peak RSS on an already
memory-tight node and invites an OOM kill — the exact failure that used to
freeze uploads at `status=processing`.

With **remote** Docling (`DOCLING=remote`, the default) the worker is I/O-bound
— it waits on Scaleway — so 2–4 parallel jobs are safe and roughly linear:

```bash
PAGEINDEX_WORKER_MAX_JOBS=4 make worker
```

**Do not raise it against `DOCLING=local`.** There the conversion runs in your
own process tree and the memory is yours to pay for.

The value is clamped to `[1, 4]` (`MAX_JOBS_CEILING` in `worker.py`); anything
higher, lower, or unparseable falls back inside that range rather than being
trusted, so a typo or a stray remote-profile setting cannot OOM the worker.
Raising the ceiling is a deliberate code change.

## Running things

```bash
make up / make down       # server + worker as host processes, logs in .run/
make serve / make worker  # same, foreground, one per shell
make preflight            # prove every hop before spending LLM budget
make ingest               # doc_store/ -> ingestion          [DIR=other/folder]
make ingest-dry-run       # list what would be submitted
make ingest-minio         # ingest from the bucket instead   [PREFIX=some/folder/]
make help                 # all of it
```
